# 传声筒

中文 Telegram 私人双向机器人。别人给机器人发消息，你在 Telegram 里回复，对方看不到你的账号。机器人是你自己的，不经过任何第三方。

贴一个 Token，在机器人里点一下就能用。不用查数字 ID，不用域名，也不用另开后台，不会打命令也能管理：所有操作都在 Telegram 里点按钮。

## 部署

先在 Telegram 打开 [@BotFather](https://t.me/BotFather)，发 `/newbot`，按提示取名，拿到一串 Token。

需要 Linux 和 root 权限。登录服务器，运行：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/dodo258/tg-botsx/main/deploy/install.sh)
```

提示找不到 curl 的话，先运行 `apt update && apt install -y curl`。没有 Docker 时脚本会问你要不要装。

全程是中文问答，只有两步：

1. **要不要网页管理。** 只跑一个机器人可以不要，这样服务器不开任何端口。要给多个人开机器人就选用域名那项，证书会自动申请并续期。
2. **粘贴 Token。** 可以一次粘贴多个，一行一个。选了网页管理的话也可以先跳过，部署好再到网页上加。

然后在 Telegram 打开你的机器人，点「开始」，再点和终端上一样的图案就绑定好了，手机和电脑都一样。图案只有服务器上看得到，别人只能猜，猜错一次按钮就失效，这时用终端里给的链接绑定。第一次绑定 7 天内有效，过期了运行 `tgbot claim`。终端会显示是谁绑定的；不是你本人的话，运行 `tgbot claim` 用新链接换回来（已有管理员时，换人链接 10 分钟内有效）。

之后运行 `tgbot` 打开管理菜单：

```text
tgbot add             新增机器人，可以一次粘贴多个 Token
tgbot list            查看所有机器人
tgbot web             网页管理地址
tgbot status          状态和最近日志
tgbot logs            实时日志
tgbot restart         重启，改了 .env 也用它
tgbot update          更新到最新版（会先备份）
tgbot backup          备份所有机器人的聊天数据到 /opt/tg-botsx/backups
tgbot restore 文件    恢复备份
tgbot claim           重新生成绑定方式
tgbot token           更换 Token
tgbot uninstall       卸载，默认保留数据
```

管理某一个机器人时带上名字，比如 `tgbot shop status`、`tgbot shop backup`。不写名字就是默认机器人。

备份的是聊天数据库。其他机器人的 Token 和网页账号不在备份里，换服务器时要重新添加。

服务器连不上 Telegram（国内常见）时，在 `/opt/tg-botsx/.env` 里配代理或反代，写法见 [.env.example](.env.example)，然后 `tgbot restart`。

### 给朋友开机器人

一台服务器能跑很多个机器人，每个有自己的 Token、管理员和数据库，数据互不相通。

在网页管理里点「添加机器人」，或在服务器上运行 `tgbot add`，可以一次粘贴多个 Token。然后把机器人的用户名发给朋友，他私聊机器人，点「成为管理员」就能用了。

谁先点算谁。不想让朋友操作，也怕被别人抢先，添加时填上对方的 @用户名：他私聊机器人就直接成为管理员，不用点任何按钮，别人也抢不走（对方的 Telegram 账号要设置过用户名）。

想换人时到网页里点「管理」重新指定，聊天记录保留。这个机器人已经有联系人的话，留空不会开放给谁先点算谁（老客户点一下就能看到别人的聊天记录），网页会给一个一次性链接，发给新管理员就行。换人后，旧管理员绑定的话题群也会解绑。

这里的隔离是机器人之间的：有服务器 root 权限的人能读到所有 Token 和聊天记录。替别人开之前请告诉对方；不想让你看到的人，应该部署到自己的服务器。

### 网页管理（可选）

只跑一个机器人不需要它。要给多个人开机器人，网页会方便很多：添加机器人、看谁在用、重新指定管理员、改第一次的自动回复（文字加图片）和验证开关。网页看不到聊天内容和 Token。

安装时会问要不要。之后也能随时开关：

```text
tgbot web on 域名     用自己的域名，自动申请 Let's Encrypt 证书，到期前自动续
tgbot web on          没有域名，开一个随机端口，用自签名证书，第一次打开浏览器会提示不安全
tgbot web off         关掉，对外端口也关了，机器人不受影响
tgbot web             看地址和证书到期时间
tgbot web-password    重设账号密码，已登录的设备会立刻失效
```

用域名之前要做两件事：把域名解析到这台服务器，在云服务商的防火墙（安全组）放行 80 和 443 端口。申请不到证书时，脚本会说明原因，并先用自签名证书把网页开起来，不会让你打不开。解决后再运行一次 `tgbot web on 域名`。

服务器的 80、443 被别的程序占着时，可以放在 Cloudflare 代理后面（SSL 模式选 Full）：

```bash
WEB_PORT=2053 WEB_URL=https://bot.example.com WEB_IP_HEADER=cf-connecting-ip tgbot web on
```

2053 是 Cloudflare 支持的端口之一，要在 Cloudflare 加一条 Origin Rule，把这个域名的目标端口改成 2053，访问时才不用带端口。

### 不用 Docker

只适合跑一个机器人，没有 `tgbot` 命令。需要 Node.js 22.18+（要用代理时 22.21+），Ubuntu 上用官方压缩包时还要 `apt install libatomic1`。把仓库放到 `/opt/tg-botsx`，写好 `.env`，用 [deploy/tg-botsx.service](deploy/tg-botsx.service) 启动，绑定方式看 `journalctl -u tg-botsx -e`。运行时没有第三方依赖，不用 `npm install`。

## 怎么用

**回复别人**：别人的消息会转到你和机器人的私聊里，长按那条消息点「回复」就是回复对方。消息被顶上去找不到了，点菜单打开面板，在「最近会话」里点他的名字（有未读的排在前面），或者按名字、@用户名搜索，再点「选中，直接回复」，之后直接打字就是发给他，首页最上面会一直显示正在回复谁。发出去后你的消息上会出现 👌，发不出去会直接告诉你原因，比如对方拉黑了机器人。

**对方看到什么**：第一次私信时（不管有没有点「开始」）收到你设的自动回复，可以是文字加一张图片，在网页或 `/settings` 里改。之后每条消息上只出现一个 👌 表示送到了，隔了 30 天再来才回一句，不打扰。

**不用打字**：点输入框左边的菜单，常用功能都在里面，点一下就执行，要填内容时机器人会接着问。操作留下的消息（面板、提示、点过的命令）默认 24 小时后自动删掉，聊天窗口保持干净，别人的私信和你的回复不会动。可以在网页或 设置 → 数据 里改成 1 小时、6 小时或不清理。

**定时发送**：面板里点「定时发送」，或在网页上点机器人的「定时发送」。发文字、图片或图文，可以只发一次，也可以每天或每周发，一天能设多个时间，一周能选多天，比如每周一、三、五的 9:00 和 18:30。私聊过机器人的人都会收到，已屏蔽和拉黑机器人的不发。服务器停机超过 6 小时错过的不补发，会告诉你。

**多人协作**：建一个开了「话题」的超级群，在面板的 设置 → 消息收在哪 里点「绑定话题群」，选这个群并确认给机器人管理员权限。没有自动绑定的话，在群里发 `/bindgroup`。之后每个联系人有自己的话题，群里的人都能回复。以 `//` 开头的话只留在群里，不会发给对方。

**管理面板**：点输入框旁边的菜单里的「打开管理面板」，或发 `/start`。首页放常用的：会话、搜索、快捷回复、隔离区、群发、统计、设置；关键词回复、屏蔽名单、清理、导出、运行状态收在「更多」里。全部点按钮。要填内容时机器人会一步步问你，点「取消」随时退出。

**联系人卡片**：每个联系人的卡片上可以点「快捷回复」直接发一句常用的话，点「撤回上一条」撤回刚发的消息，还能看聊天记录、写备注、屏蔽。

习惯打字的话，下面这些命令也都能用：

| 命令 | 作用 |
|---|---|
| `/list` | 最近会话 |
| `/search 关键词` | 按名字、用户名、ID、备注搜索 |
| `/history` | 聊天记录 |
| `/note 内容` | 给联系人写备注 |
| `/block` `/unblock` | 屏蔽和解除 |
| `/del` | 回复自己发的消息来撤回（48 小时内） |
| `/q 名字` | 发快捷回复，`/qadd 名字 内容` 添加 |
| `/filtered` | 隔离区，被拦下的消息可以放行 |
| `/stats` | 收发量、新联系人、平均首次回复时间 |
| `/rule` | 关键词自动回复（主人） |
| `/broadcast` | 回复一条消息后群发（主人） |
| `/status` | 运行状态（主人） |
| `/cleanup` `/export` | 清理和导出数据（主人） |

命令后面可以跟数字 ID，比如 `/history 123456`；不跟就用当前话题、引用的消息或选中的会话。

## 它做了什么

**消息不丢**
- 验证前发的消息先留着，通过后自动转过来，对方不用重发。
- 转发失败（比如被 Telegram 限流）会记下来，定时补发。
- 被拦截的消息进隔离区，不是直接丢弃。
- 话题被删了自动重建，被关了自动重开。
- 相册保持相册，不拆成一张张。

**消息不串**
- 回复关系全部记在自己的映射表里，不依赖对方的转发隐私设置。
- 消息按顺序逐条处理。

**同步**
- 对方改了消息，这边跟着改，并留下原文。你改了消息，对方那边也跟着改。
- 表态双向同步。

**防骚扰**
- 第一次发消息要答一道 10 以内的加减题。点到旧题、超时都不算错；连错 3 次才锁 1 小时。
- 可以按关键词、新联系人发链接、转发内容拦截，也可以让新联系人先审核。
- 单人刷屏自动暂停 10 分钟。陌生人突然大量涌入时自动进入防护，已验证的联系人不受影响。

**安全**
- 默认不开任何端口，机器人只往外连 Telegram，容器也不给多余权限。开了网页管理才对外：没有域名时一个随机 HTTPS 端口，用域名时 80 和 443。要账号密码，看不到聊天内容和 Token。
- 只有主人能改设置、群发、导出。其他群里的消息一律不碰。
- 不收集 IP 和设备信息。机器人只看得到 Telegram 给的名字和用户名。

## 做不到的

- **对方删除消息同步不了**：Telegram 不把这个事件告诉普通机器人。
- **撤回有时限**：Telegram 只允许删 48 小时内的消息。
- **群里转发有限速**：Telegram 限制同一个群约每分钟 20 条。消息高峰时会排队补发，有延迟但不丢。量大的话用私聊模式。
- **私聊话题是实验功能**：不用建群也有话题，但这个开关是机器人全局的，普通用户的聊天界面也可能变化。

## 数据和隐私

你部署的机器人，数据就在你自己的服务器里，没有中心服务。聊天内容默认保留 180 天后自动抹掉（`/settings` → 数据 里可改），联系人和回复关系保留，老消息依然能回复。

如果你公开使用这个机器人，你就是这些数据的控制者，请按当地法律告知用户。

## 费用

只有服务器本身的费用。机器人很省资源，最便宜的 VPS 就够：所有机器人共用一个进程，实测 1 个约 80 MB，10 个约 100 MB，50 个约 130 MB（刚启动、没有聊天数据时，消息多了会高一些）；Docker 本身的占用另算。
